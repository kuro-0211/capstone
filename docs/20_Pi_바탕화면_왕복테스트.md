# 파트 20 — Pi 바탕화면 테스트 폴더와 실제 PC↔Pi 왕복

검증일: 2026-10-11

## 준비한 위치와 환경

Pi에 `/home/pi/Desktop/PetMind_Test` 폴더를 만들었다. 전용 `.venv`는 Python 3.13.5이며 requests 2.34.2와 의존성을 설치했다. 기존 시스템 Python 환경은 변경하지 않았다.

파일: `device_agent.py`, `pi_probe.py`, `run_once.sh`, `README.md`, `pi_verification.json`, `TEST_RESULT.md`, 명령 결과 캐시 `commands.db`.

PC의 127.0.0.1:8010 API를 SSH 역방향 터널로 Pi의 127.0.0.1:18010에 연결했다. 실제 리스닝 주소가 Pi loopback임을 확인했다. PC 가상 에이전트는 시험 중 중지해 Pi가 시험 명령을 처리하도록 했다.

## 실제 검증 결과

| 시험 | 확인한 결과 |
|---|---|
| Pi 환경·API 연결 | iot / ARM64 / Python 3.13.5, PC health HTTP 200 |
| 완료 | PC 승인 → Pi 수신·확인·완료 → PC DB completed |
| 실패 | PC 승인 → Pi 모의 실패 보고 → PC DB failed |
| 중복 조회 | 종료 명령이 pending 목록에서 제외되어 Pi 재조회 결과 빈 배열 |
| 늦은 응답 | 종료 후 acknowledged 응답은 HTTP 409, 종료 상태 유지 |
| 무응답 | Pi를 실행하지 않은 명령은 실제 약 30초 뒤 timed_out |

모든 프로토콜 테스트가 통과했다. 음악 동작은 **실제 Pi에서 실행한 가상 장치 코드**이며 스피커·GPIO·카메라·마이크를 작동시킨 것은 아니다. SSH·Pi OS 자체를 재부팅하거나 강제로 네트워크를 끊는 시험은 하지 않았다.

## 최소 코드 변경

`petmind/device_agent.py`에 `--command-id`를 추가해 시험 명령 하나만 처리할 수 있게 했다. 다른 대기 명령을 시험의 실패 응답으로 처리하지 않도록 격리한다. 전체 Python 회귀 검증 **44 passed**. PC/기존 에이전트의 기본 사용법은 유지된다.

재현 코드: `scripts/verify_pi.py`, `scripts/pi_probe.py`, `scripts/pi_run_once.sh`, `scripts/PI_TEST_README.md`. 원본 결과는 `docs/evidence/pi_verification.json`과 Pi 폴더의 동일 이름 파일에 저장했다.

## 이후 실행

Pi 폴더의 README에 PC SSH 터널과 Pi 에이전트 실행 명령을 저장했다. 테스트 터널은 종료하고 PC 기본 가상 장치를 복구한다. 다시 시험할 때 README의 SSH 터널을 먼저 열어야 한다. 실제 음악·센서, Pi 재부팅·네트워크 장애 복구는 후속 항목이다.
