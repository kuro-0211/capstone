# Pi 실시간 카메라 미리보기

자동 외출 수집과 함께 사용할 때는 [자동 외출 실행 안내](AUTOMATIC_OUTING.md)를 따른다. 아래 독립 미리보기와 자동 수집 에이전트를 동시에 실행하지 않는다. 자동 수집에서는 하나의 캡처를 공유하며 최근 장면이 약 5초 단위로 갱신된다.

대시보드 상단의 **실시간 카메라 → 카메라 화면 열기 → 카메라 보기 시작**으로 최근 화면을 확인한다. 약 2fps JPEG 미리보기이며 음성·영상 녹화나 분석을 시작하지 않는다. 저장된 사건 영상은 외출 기록의 원본 근거에서 별도로 확인한다. 미연결·잘못된 응답·시간초과 때 화면을 지우고 연결 불가를 표시한다. 보기 중지 또는 탭 숨김 시 요청을 멈춘다.

## 장비 연결 후 설정

현재는 사이트·API·Pi 실행 스크립트만 구현했다. 2026-10-12 SSH 검사에서는 USB 웹캠이 인식되지 않아 실장비 재생 검증은 보류했다. CSI 카메라는 이 V4L2 USB 입력 스크립트로 검증하지 않았다.

1. Pi에 USB 웹캠을 연결하고 `v4l2-ctl --list-devices`로 실제 캡처 장치 경로를 확인한다. `/dev/video*`가 존재한다는 이유만으로 웹캠이라고 판단하지 않는다.
2. `scripts/pi_camera_preview.py`를 Pi의 테스트 폴더에 복사한다. 시스템 FFmpeg가 필요하다. Pi에서 `python3 pi_camera_preview.py --device /dev/video0`을 실행한다. 경로는 확인된 캡처 장치로 바꾼다.
3. PC에서 `ssh -N -L 18081:127.0.0.1:18081 -o ExitOnForwardFailure=yes raspberrypi-ai`를 실행하고 유지한다.
4. 저장소 루트 `.env`에 `PETMIND_CAMERA_SNAPSHOT_URL=http://127.0.0.1:18081/snapshot.jpg`를 설정하고 FastAPI를 재시작한다.
5. 사이트에서 카메라 보기를 시작한다. 웹캠·SSH를 끊었을 때 이전 화면이 사라지는지, 다시 연결 후 새 화면을 받는지 확인한다. FFmpeg가 종료된 경우 Pi 스크립트를 재시작한다.

Pi 서비스와 PC API는 루프백에서 사용한다. 공용 인터넷에 노출하지 않는다. 영상 프레임은 메모리에서만 유지하며 3초 이상 갱신되지 않으면 Pi 서비스는 503을 반환한다. PC API는 고정된 서버 설정만 읽고 브라우저로부터 임의 주소를 받지 않는다.

## 현재 제한과 후속 확인

- 실시간 미리보기는 소리 없는 저속 프레임 갱신이며 네트워크 지연이 있다.
- 사건 녹화 프로세스와 이 스크립트가 같은 USB 장치를 동시에 열 수 있는지는 장치마다 다르다. 동시 사용은 아직 미검증이다. 충돌하면 단독 실행으로 확인하고, 동시 운영 전 캡처 단일화/프레임 공유를 구현해야 한다.
- UI와 미연결 API, 유효/비정상/과대 응답 및 단절 처리는 자동 테스트했다. 실제 Pi 프레임·장시간 운용은 장비 연결 후 확인한다.
- 변경: `camera_panel.dart`, 대시보드 연결, `routers/camera.py`, API 등록, Pi 스크립트, 환경 예시, 회귀 테스트.
- Python 전체 128개, Flutter 전체 20개 통과. 장비에 스크립트를 배포하거나 카메라를 켜지는 않았다.
