# 음성 중심 PetMind 개발 기록

## 유지하는 핵심 주제

영상·소리만으로 감정·질환을 단정하지 않는다. 관찰 신호를 반려견별로 기록하고, 과거 관찰과 보호자 의견을 근거로 제시해 보호자가 케어 제안을 검토하도록 돕는다. 추가 센서와 급식기는 제외한다.

## 변경된 개발 방향

- 음성 LSTM을 핵심 분석 후보로 평가한다. 기존 영상 LSTM 체크포인트는 보존하며, 웹캠은 이벤트 장면 확인에 우선 사용한다.
- 공개 데이터로 기본 성능을 평가한 뒤 실제 사용자 환경의 오류를 수집한다.
- 개인 기록·RAG 활용과 공통 모델 학습 참여 동의를 분리한다. 보호자 의견은 출처가 표시된 의견이며 즉시 자동 학습 정답으로 사용하지 않는다.
- 모델 불확실성·모델 간 불일치에 따른 확인 큐와 일반 구간 표본 확인을 함께 제공한다. 미검출 구간도 검토해야 누락률을 평가할 수 있다.

## 완료 기준과 남은 작업

1. 외출 시작 → 관찰 → 음원·영상 구간 확인 → 보호자 의견 → 귀가 요약·근거 비교를 브라우저에서 연속 검증한다.
2. ESC-50의 공식 원본 그룹 분할을 유지해 에너지 방식, 단순 음성 분류기, 음성 LSTM을 비교한다. FSD50K의 라벨·라이선스·중복 원본을 검토해 확장한다.
3. 사전학습 오디오 특징 모델을 별도로 비교한다. 사전학습 데이터 중복 여부·라이선스·실행 비용을 기록하며, 최신 모델이라는 이유로 채택하지 않는다.
4. 사용자 음원 입력, 소리 구간 재생, 확인 라벨 수정, 상황 메모를 연결한다. 개인 기록과 학습 참여 선택, 보관 기간, 원본 삭제·참여 철회를 제공한다.
5. 검수된 학습 참여 자료만 내보내고 개체·원본 단위 분할을 유지한다. 자동 재학습·자동 배포는 하지 않으며 개선이 확인된 후보만 명시적으로 채택한다.
6. RAG에 관찰 사실과 보호자 의견의 출처·근거 링크를 구분해 연결하고 고정 질문 세트로 비교한다.
7. 전체 Python·Flutter 회귀 검증과 실제 브라우저 시연 결과를 기록한다. 사용자 실데이터가 없으면 개인화 성능 개선을 완료로 주장하지 않는다.

## 이번 작업

- `scripts.prepare_esc50`: 공식 저장소 리비전 `33c8ce9eb2cf0b1c2f8bcf322eb349b6be34dbb6` 고정, 전체 2,000개 WAV 검증·SHA256·라벨·라이선스·원본 그룹 기록. 다운로드 중단 시 이미 검증 가능한 파일을 재사용한다.
- `pet_monitor.audio_lstm`: 16 kHz 모노, 5초 구간의 log-mel 특징과 별도 음성 LSTM·평균/표준편차 분류기를 구현했다. 영상 모델 파일은 변경하지 않는다.
- `scripts.train_audio_baselines`: 공식 fold 1–3 학습, 4 검증, 5 최종 평가. 정규화는 학습 데이터에서만 계산하고 epoch·임계값은 검증 데이터에서만 선택한다. 에너지 기준과 비교한다.
- 최종 평가의 양성은 개 소리 8개뿐이다. 좋은 수치가 나와도 실제 가정 환경이나 감정 정확도로 해석할 수 없다. Dog 파일 라벨과 정확한 짖음 구간 라벨을 구분한다.
- 기존 파일럿 20개는 fold 1이므로 이번에는 학습 쪽에만 포함된다. 평가 결과를 보고 임계값을 다시 조정하면 해당 평가는 개발 평가로 재분류해야 한다.

## 첫 공개 데이터 비교 결과

2,000개 WAV를 확보했다. 공식 메타데이터에서 서로 다른 소리 클래스가 같은 원본 ID를 사용하는 사례를 발견했다. 평가 fold 5는 유지하고 원본이 겹치는 검증 fold 4의 2개 파일을 제외해 학습 1,200개·검증 398개·평가 400개로 실험했다. 같은 원본 ID와 정확히 같은 해시가 서로 다른 분할에 남지 않도록 검사한다.

| 방식 | 개 소리 검출 / 8 | 기타 소리 오탐 / 392 | 정밀도 | 재현율 | F1 |
|---|---:|---:|---:|---:|---:|
| 에너지 후보 감지 | 6 | 172 | 3.37% | 75% | 0.0645 |
| log-mel 평균·표준편차 분류기 | 2 | 15 | 11.76% | 25% | 0.1600 |
| log-mel 음성 LSTM | 5 | 3 | 62.5% | 62.5% | 0.6250 |

음성 LSTM은 검증 fold에서 선택한 epoch 18, 임계값 0.9다. 평가 결과를 이용해 재조정하지 않았다. 오탐 감소와 함께 개 소리 누락이 1개 늘었다. 양성이 8개뿐인 단일 분할 실험이며 실제 가정 환경 정확도나 유의한 일반화 향상으로 주장하지 않는다. checkpoint 메타데이터의 NumPy 임계값을 Python float로 저장하도록 수정하고 동일 시드·절차로 재생성했다. 안전한 weights-only 로딩을 유지한다.

## 사용자 데이터 API 진행

- 30초 이하 WAV 업로드와 저장 동의, 별도 학습 참여 선택, 1~30일 보관 기간을 구현했다.
- 외출의 `uploaded_audio` 모드와 `user_audio` 출처를 추가했다. 영상 관찰이 없는 시간은 판단 불가로 기록한다.
- 음성 LSTM은 실험 결과로 별도 표시하고 에너지 이벤트 수를 LSTM 짖음 횟수로 바꾸지 않는다. 5초 구간별 점수와 마지막 구간 padding 여부를 기록한다.
- 보호자 확인 라벨·메모와 수정, 학습 참여 철회, 원본 삭제를 제공한다. 만료 원본은 음원 API 접근 시 정리한다. 서버가 꺼져 있어도 즉시 삭제된다고 보장하지 않으며 주기적 정리는 후속 작업이다.
- 보호자 의견을 외출 RAG의 별도 근거 종류로 연결했다. 의견을 바꾸면 학습 검수 완료 상태는 초기화된다.
- 현재 pet_id는 기록 구분용이며 인증 수단이 아니다. 실제 다중 사용자 서비스 배포 전 인증·접근 제어가 필요하다. 현재는 로컬 단일 가정 개발 환경이다.

## 화면 연결과 브라우저 검증

- Flutter 음원 패널: 개인 저장 동의와 학습 참여 별도 선택, 보관 기간, WAV 업로드, 실험 점수, 확인 의견 입력·수정, 학습 참여 철회, 원본 삭제 확인창을 연결했다.
- 의견 창 닫힘 중 TextEditingController가 먼저 해제되는 문제를 위젯 테스트로 발견해 수정했다. Flutter 테스트 3개 통과, 정적 분석과 웹 빌드 통과.
- 로컬 백엔드 8011 / 웹 8022의 별도 시연 DB에서 브라우저로 사용자 음원 외출 시작 → 공개 ESC-50 샘플 업로드 → 의견 저장·수정 → 귀가 종료 → MCP 근거 요약 표시를 확인했다. 실제 사용자 연구가 아니라 공개 자료를 이용한 기능 시연이다.
- 원본 WAV 직접 탐색이 브라우저에서 차단되어 HTML 오디오 플레이어로 수정했다. 플레이어에서 재생 버튼 실행 후 currentTime=5, duration=5, ended=true를 확인했다. `docs/evidence/audio_browser_playback.json`에 기록했다.
- 화면 캡처는 연결된 브라우저의 캡처 명령이 시간초과해 확보하지 못했다. 캡처·시연 영상 완료로 주장하지 않는다.
- 음원 API 추가 후 Python 테스트 83개 통과. 플레이어 변경 이후 회귀 검증 결과는 후속 확인한다.

## 학습 자료 검수와 보관 정책 구현

- 학습 동의·보호자 의견·원본 해시·보관 기간을 확인한 뒤 운영자가 소리 종류(`dog`/`other`)를 별도로 검수한다. TV의 개 소리는 위치가 외부여도 음향 정답은 dog일 수 있으므로 보호자의 상황 라벨을 자동 변환하지 않는다.
- `scripts.review_user_audio verify`는 검수자·이유·의견 해시·원본 해시를 기록한다. `export`는 조건을 충족한 목록만 만들고 원본을 복사하지 않는다. `validate`는 현재 동의·만료·삭제·라벨·원본·분할 상태를 다시 확인한다. 이 목록을 소비하는 후속 학습은 매 실행 시 재검증해야 한다.
- 같은 반려견 또는 같은 원본 해시로 연결된 자료는 하나의 그룹으로 묶는다. 정확한 중복은 제외하고, 중복 원본의 정답이 충돌하면 모두 제외한다. 신규 자료로 그룹이 합쳐지면 기존 목록의 분할도 재검증한다. 소수 개체로는 세 분할이 모두 채워지지 않을 수 있으며 부족한 상태로 성능을 주장하지 않는다.
- 보호자 의견 수정·동의 철회·만료·삭제·원본 변경 시 기존 학습 목록을 무효화한다. 이미 학습한 모델의 역학습은 구현하지 않았다. 현재 개인 자료를 이용한 재학습은 실행하지 않았다.
- 확인 추천 큐는 모델 불일치·임계값 근처 점수와 일반 음원 표본을 함께 제시한다. 모든 점수는 미보정 점수이며 신뢰 확률로 해석하지 않는다. 현재 후보 범위는 업로드한 음원뿐이다.
- 서버 시작 시 및 실행 중 60초 간격으로 만료 원본을 정리한다. 서버 중단 중에는 삭제가 실행되지 않으며 다음 시작 시 정리한다.
- Python 테스트 92개, Flutter 테스트 3개 통과. 동의 없는 자료 제외·독립 검수·의견/동의/파일 변경 후 목록 무효화·중복 충돌·일반 표본 포함·백그라운드 만료 삭제를 검증했다.

운영자 명령 예시(실제 청취·검수 후 실행):

```powershell
python -m scripts.review_user_audio verify CLIP_ID --label dog --reviewer REVIEWER --reason "청취 검수 근거"
python -m scripts.review_user_audio export
python -m scripts.review_user_audio validate artifacts/user_audio_training/manifest.json
```

RAG 비교 평가 및 최종 브라우저 전체 검증은 아직 남아 있다. 이 문서는 전체 완료 보고가 아니다.

## FSD50K 외부 비교와 추가 학습 (2026-10-11)

- 공식 FSD50K에서 CC0/CC BY 음원을 고정 해시 순서로 선택했다. ESC와 같은 Freesound 원본 ID를 제외했다. 공식 평가 분할 120개(개 소리 60/그 외 60), 공식 학습 분할 240개를 확보했다. 원본은 Git에 포함하지 않는다.
- 다운로드는 공식 메타데이터 체크섬, ZIP 항목 CRC32 및 로컬 SHA256으로 확인했다. 전체 다중 ZIP을 다운로드한 검증과는 구분한다.
- 기존 모델의 ESC 검증 임계값을 그대로 고정한 FSD 평가:

| 모델 | 정밀도 | 재현율 | F1 | 비개 음원 오탐 |
|---|---:|---:|---:|---:|
| 에너지 후보 | 52.0% | 65.0% | 57.8% | 36/60 |
| pooled 음향 모델 | 52.4% | 36.7% | 43.1% | 20/60 |
| 오디오 LSTM | 94.4% | 28.3% | 43.6% | 1/60 |
| CLAP 고정 텍스트 비교 | 100% | 71.7% | 83.5% | 0/60 |

근거: `evidence/audio_external_fsd50k.json`, `evidence/clap_fsd50k_comparison.json`. CLAP은 공개 사전학습 자료에 ESC/Freesound가 포함되었을 가능성을 배제하지 못하므로 독립 검증이나 일반적인 정확도 향상으로 주장하지 않는다. 120개 균형 표본은 실제 가정의 소리 비율을 나타내지 않는다. 현재 모델 자동 교체는 하지 않았다.

- `scripts/train_audio_mil.py`를 추가했다. 긴 음원 전체를 5초 구간으로 분할하고 개 소리 점수의 최대값으로 음원 단위 정답을 학습한다. 첫 5초만 사용하거나 모든 구간에 개 소리 정답을 붙이는 오류를 피한다. 정확한 발성 시점 정답을 새로 만든 것은 아니다.
- 기존 체크포인트에서 추가 학습하되 별도 `esc50_fsd_mil_*.pt`에 저장한다. 공식 FSD 학습 자료만 추가하며 ESC 검증 자료로 회차·임계값을 선택한다. 기존 평가 자료는 이미 결과를 본 개발 비교용이며 새로운 맹검 평가라고 부르지 않는다.
- `tests/test_audio_mil.py`에서 후반 소리 보존, 음원 단위 양성 학습, 원본 ID/해시 중복 거부를 확인했다. 전체 Python **97개 테스트 통과 (14.04초)**.
- 추가 학습을 실제 완료했다. LSTM은 ESC 검증 F1이 학습 전 0.889에서 추가 학습 후 최고 0.824로 낮아졌다. 정해 둔 선택 규칙에 따라 **학습 전 epoch 0이 선택**되었고 평가 결과도 기존과 동일했다. FSD 자료 추가만으로 개선되었다는 주장은 하지 않으며 추가 학습 가중치를 운영에 채택하지 않았다. pooled 후보는 FSD F1 43.1%→49.1%였지만 ESC F1 16.0%→14.8%로 낮아져 채택하지 않았다. 결과와 전체 검증 이력은 `evidence/audio_mil_comparison.json`에 저장했다.
- 다음 실험에서는 별도의 FSD 검증 분할과 실제 배경 소음 조건을 포함한 검증 설계를 먼저 고정해야 한다. 현재 평가 자료로 반복 임계값 조정은 하지 않는다. 사용자 데이터는 감지 사례뿐 아니라 놓친 사례·일반 구간도 확보해야 한다.

```powershell
python -m scripts.prepare_fsd50k_subset --split eval --per-class 60
python -m scripts.prepare_fsd50k_subset --split dev --per-class 120
python -m scripts.evaluate_audio_external
python -m scripts.train_audio_mil
```

사용자 자료는 개인 기록/RAG 활용과 공통 모델 학습을 분리한다. 보호자 의견은 독립적인 음향 정답으로 자동 간주하지 않는다. 실제 사용자의 자료로 학습하거나 개인화 정확도를 검증한 결과는 아직 없다. 외부 사용자 모집 전에는 인증과 사용자별 접근 제어가 필요하며 현재 API는 로컬 단일 가정 시제품이다.

## 세션 검색과 하루 근거 설명

- 기존 검색은 `if/elif`로 한 종류의 질문만 선택하고 오래된 순서의 첫 8개를 반환했다. 복합 질문의 보호자 의견이 누락되고 긴 세션의 최근 의견도 검색에서 밀렸다.
- `services/outing_retrieval.py`에서 질문의 여러 주제를 함께 인식하고 주제별 근거를 우선 배치한다. 세부 관찰·의견은 최근 순서로 제공하며 8개 한도를 유지한다. 보호자 메모 안의 명령은 검색 기준으로 사용하지 않는다.
- 고정 개발자 작성 질문 16개를 이전 필터와 비교했다. 필요한 근거 포함 성공은 **8/16 → 16/16**이었다. 이는 합성 기록 기반 회귀 평가이며 독립 사용자 질문·실제 Gemini 응답 정확도는 아니다. `tests/fixtures/outing_retrieval_questions.json`과 `evidence/outing_retrieval_comparison.json`에 질문·해시·결과·한계를 기록했다.
- `POST /outings/day/explain?day=YYYY-MM-DD`와 Flutter의 ‘하루 근거 설명’을 추가했다. KST 날짜와 반려견 범위로 집계한 수치, 의견, 관찰별 원본 근거를 제공한다. 하루 검색은 `local-day`로 표시하며 MCP 사용으로 주장하지 않는다. 수치·문장은 공통 서버 렌더러에서 만들고 Gemini는 허용된 근거 ID만 선택한다.
- Python **99개 통과 (14.15초)**. 날짜 경계 제외, 다른 반려견의 빈 결과, 하루 수치와 근거 ID 일치를 API 테스트로 확인했다. Flutter **4개 통과**, 정적 분석 통과. 하루 설명 버튼·반려견/날짜 요청·원본 없는 근거 안내를 위젯 테스트로 확인했다. 최신 브라우저 실제 클릭 검증은 아직 남았다.

```powershell
python -m scripts.evaluate_outing_retrieval
```

## 최신 브라우저 연속 시연 검증

- 최신 코드로 로컬 API 8011을 재시작하고 웹 8022를 재빌드했다. 기존 시연 DB `artifacts/p0_validation/web.db`를 유지했다. 제공자는 `rule`, 세션 검색은 실제 MCP이며 이번 시연을 Gemini 응답으로 표시하지 않는다.
- ‘하루 근거 설명’을 브라우저에서 눌러 공개 음원 표본 5초, 영상 판단 불가 5초, 짖음 후보 1회와 보호자 의견을 확인했다. `evidence/day_browser_summary.txt`에 화면의 접근성 텍스트를 저장했다.
- DAVIS 5fps 재생 영상을 H.264로 변환하고 새 파일을 다시 분석했다. 원본 해시·부모 해시·라이선스·변환 내역은 무시된 미디어 manifest에 남겼다. 원본 촬영 시간이나 실제 행동 정답을 검증한 것이 아니다.
- 브라우저에서 준비된 영상 모드 선택 → 외출 시작 → 공개 영상·음원 관찰 → 귀가 종료 → MCP 근거 요약 → 근거 #2 → 영상 플레이어 순서로 실행했다. 표본 5초 / 영상 판단 불가 3.2초 / 이동 후보 1.8초 / 짖음 후보 1회가 표시됐다. `evidence/video_browser_summary.txt` 참조.
- Flutter 접근성 레이어가 iframe 재생 버튼의 클릭을 가리는 오류를 재현했다. `clip_view_web.dart`에 새 탭 재생 버튼을 추가했다. 수정된 화면에서 버튼을 직접 눌러 플레이어가 열리는 것을 확인했다. 팝업 iframe 자체의 접근성 겹침은 남아 있으므로 안내와 별도 플레이어를 제공한다.
- 플레이어에서 직접 재생을 눌러 7초에서 시작(paused=false), 12초에 종료(ended=true, paused=true, readyState=4, error=null)를 확인했다. `evidence/video_browser_playback.json`에 기록했다. 이는 실제 브라우저 재생 증거이며 녹화 영상 파일은 아니다.
- 수정 이후 Python 99개(15.48초), Flutter 4개 테스트, Flutter 정적 분석 및 웹 빌드 통과. 빌드 명령은 `flutter build web --dart-define=PETMIND_API_BASE=http://127.0.0.1:8011`이다.

남은 검증은 실제 Gemini의 새 요약 경로, 구현에 사용하지 않은 질문 세트 평가, 동의 철회·추천 큐의 최신 브라우저 흐름, 발표 자료 정리와 전체 요구사항 감사다. 스크린샷·녹화는 아직 확보하지 않았다. 실제 사용자 데이터를 통한 정확도 향상도 미검증이다.

## 실제 Gemini와 별도 질문 평가

- `scripts/verify_outing_gemini.py`를 추가하고 로컬 키를 환경으로만 읽어 실행했다. 실제 모델 `gemini-3.5-flash-lite`로 세션 수치·하루 요약·보호자 의견 3건을 검증했다. 개인 DB와 원본 음원은 읽거나 전송하지 않았고 고정 가상 관찰만 사용했다.
- 3건 모두 실제 Gemini 제공자, 대체 응답 없음, 필요한 주제 선택, 허용된 근거 ID, 원문/수치/관찰 ID 보존, 최종 문장 일치 검사를 통과했다. `evidence/outing_gemini_verification.json`에 저장했다. 3건의 연동 검증이며 모델의 일반 정확도는 아니다. MCP 전송은 별도 브라우저/API 테스트의 증거와 구분한다.
- 구현 때 사용한 16개 질문과 별개로 20개 질문을 작성해 같은 합성 기록에서 비교했다. 이전 방식 **8/20**, 개선 방식 **15/20**에서 필요한 근거를 모두 포함했다. 질문·구현 SHA256과 실패 사례는 `evidence/outing_retrieval_holdout.json`에 남겼다.
- 이 질문 역시 같은 개발자가 작성했다. 외부 사용자/독립 평가자의 맹검 질문으로 주장하지 않는다. 초기 문항 2개는 미관찰 시간과 영상 판단 불가를 혼동하지 않도록 표현을 명확히 했으며, 수정 전후 결과는 동일했다. 이 결과를 보고 검색 코드를 재조정하지 않았다.
- 실패는 ‘분석한 분량’, ‘행동을 구분하지 못한 구간’, ‘TV였다는 확인’ 등 표현 다양성과 불확실성 질문이었다. 정해진 키워드 밖의 질문에는 기록이 있어도 부족하다고 답할 수 있다. 새로운 임베딩 검색 또는 질문 의도 분류를 실험할 때 이 20개는 개발 평가로 전환하고 새 평가 질문을 확보해야 한다.
- 전체 Python 99개 테스트 통과(13.63초). 이번 변경은 평가 스크립트·질문·기록이며 운영 모델 가중치는 바꾸지 않았다.

## 사용자 확인 추천·동의 철회 및 중복 업로드 수정

- 최신 브라우저에서 공개 ESC 음원을 개인 저장·학습 참여에 각각 동의해 업로드했다. 모델/에너지 불일치로 확인 추천 1건에 나타났고, 추천 목록에서 학습 참여 철회를 실행했다. 이후 ‘학습 참여 미동의’ 표시와 철회 버튼 제거를 확인했다. `evidence/audio_consent_browser.txt`에 저장했다. 실제 개인 자료나 공통 모델 학습은 사용하지 않았다.
- 같은 음원 재업로드가 하루 집계에 다시 더해지는 오류를 발견했다. `services/outings.py`에서 오디오 원본 SHA256을 집계 구분 기준으로 사용해 중복을 제외한다. 삭제/만료 뒤에도 해시로 중복을 판별한다. 중복 관찰의 보호자 의견과 근거 기록은 보존하고 `included_in_metrics=false`로 구분한다.
- 중복 업로드 2건의 표본 합계, 의견 2건 보존, 원본 삭제 뒤 집계 불변 회귀 테스트를 추가했다. 전체 Python **100개 통과 (13.94초)**. 재시작한 실제 API에서 관찰 #3을 중복 제외하고 하루 표본 15→10초, 후보 3→2회로 복구되는 것을 확인했다. 이는 시연 DB의 수정 검증이며 감지 성능 개선은 아니다.
- 발표·설치·시연·검증 범위·복구 절차를 [파트 34](34_음성중심_시연_완료점검.md)에 모으고 README에 최신 방향을 연결했다.

## 원본 부재 표시와 최종 회귀 확인

- DB에 영상/음원 연결이 있어도 실제 파일이 없으면 재생 버튼을 제공하지 않도록 `moment()`를 수정했다. 허용 폴더 안의 파일인지 확인하며, 기록과 집계는 남기고 원본 부재를 명시한다. 원본 변경 여부의 SHA256 검사는 실제 재생 API에서 계속 수행한다.
- 영상 파일 삭제 뒤 요약의 재생 불가 표시, 음원 파일 유실 뒤 원본 링크 제거를 회귀 테스트로 확인했다. 전체 Python **101개 통과 (14.37초)**. `pip check` 정상, `git diff --check` 오류 없음(Windows 줄바꿈 안내만 출력).
- 브라우저 캡처를 다시 실행했으나 `Page.captureScreenshot` 시간초과로 실패했다. 브라우저가 제공하는 기능 목록에는 녹화 기능이 없었다. 다른 방식의 그림을 실제 화면 캡처처럼 제공하지 않았다. 현재 증거는 실제 클릭 후 접근성 화면 텍스트와 미디어 재생 상태 JSON이며 녹화 파일은 없다.
