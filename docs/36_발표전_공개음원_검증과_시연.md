# 발표 전 공개 음원 검증과 시연 기록

기준일: 2026-10-11. 개인 반려견 자료가 없는 상태에서 공개 자료로 기능을 검증했다. 아래 수치는 실제 가정 정확도나 감정·질환 판정 성능이 아니다.

## 추가 데이터와 분할

- [ESC-50](https://github.com/karolpiczak/ESC-50)의 원본별 공식 5-fold 구분을 유지했다. 로컬 분할은 학습 1,200건, 검증 398건, 기존 평가 400건이다.
- [FSD50K](https://zenodo.org/records/4060432)의 공식 `dev/train`에서 기존 240건, `dev/val`에서 새로 110건을 확보했다. 검증 자료는 라이선스 CC0/CC BY·ESC 원본 ID 제외 조건을 통과한 Dog 50건과 비개 60건이다. 기존 `eval` 120건은 이전에 결과를 확인했으므로 **맹검 자료가 아닌 개발 비교**에만 사용했다.
- 준비 스크립트가 공식 메타데이터 체크섬, 음원 ZIP CRC32, 파일 SHA256, 출처 ID·업로더·라이선스·분할을 확인한다. 학습·검증·평가 그룹 사이에서 출처 ID와 파일 해시의 교집합은 없었다. 편집·변환된 복제본의 완전한 배제는 보장하지 못한다. 원본과 체크포인트는 `artifacts/`에만 있다.
- 평가 자료를 후보 선택에 섞는 구현 오류를 첫 실행에서 발견해 수정했고, 첫 결과를 폐기한 뒤 전체 실험을 다시 실행했다.

## 동일 조건 LSTM 비교

세 조건은 같은 5초 log-mel·LSTM 구조를 사용한다. 첫 조건은 기존 가중치·임계값 0.90, 둘째는 기존 가중치에 공식 검증 분할만으로 고른 임계값 0.85, 셋째는 공식 학습 분할에만 음량·배경 소음 증강과 음원 단위 MIL을 적용한 4 epoch 후보(임계값 0.95)다. 후보 선택은 ESC/FSD 검증 F1 평균이며 각 검증 자료의 비개 오탐률이 기존보다 5%p 이상 높아지면 제외한다.

| 조건 | 검증 평균 F1 | ESC 기존 평가 F1 / 개 소리 감지 | FSD 기존 평가 F1 / 개 소리 감지 | FSD 비개 오탐 |
|---|---:|---:|---:|---:|
| 기존 LSTM | 0.663 | 0.625 · 5/8 | 0.436 · 17/60 | 1/60 |
| 임계값만 조정 | 0.698 | 0.625 · 5/8 | 0.475 · 19/60 | 1/60 |
| 증강·MIL 후보 | **0.746** | 0.632 · 6/8 | 0.430 · 17/60 | 2/60 |

**운영 모델은 기존 LSTM을 유지한다.** 검증 점수 1위인 증강 후보가 기존 FSD 평가에서는 개 소리 감지를 개선하지 못하고 오탐이 늘었다. 임계값 후보는 개발 비교에서 나았지만, 이 결과를 보고 1위 후보 대신 골라 배포하면 기존 평가 자료에 맞춘 사후 선택이 된다. 독립적인 새 평가 자료와 가정 음향이 확보되기 전까지 채택하지 않는다. 평가 원본 수가 특히 ESC 개 소리 8건으로 적다. 정밀도는 전체 정확도가 아니며 FSD 기존 모델은 60개 중 43개를 놓쳤다.

실행 시간은 특징 추출을 제외한 미리 적재한 음원 120건의 모델 추론 합계에서 기존 약 0.052초, 증강 후보 약 0.049초였다. 이 값은 업로드·특징 추출·서버 왕복 시간이 아니고 작은 표본의 단회 측정이다. 상세 점수·혼동행렬·임계값·체크포인트/manifest 해시는 [`audio_lstm_three_way.json`](evidence/audio_lstm_three_way.json)에 남겼다.

## 짖음·낑낑·하울링 자료 조사

FSD50K 공식 CSV에는 Bark가 학습 352·검증 62·평가 122건, Growling이 각각 61·11·51건 있다. **Whimper와 Howl은 FSD50K 공개 어휘에 없다.** 기존 FSD 평가 표본에서 이진 Dog 모델은 Bark 라벨 42건 중 12건, Growling 라벨 12건 중 4건을 감지했다. 라벨은 음원 단위이고 두 종류가 겹칠 수 있으므로 이는 발성 종류 분류 정확도가 아니다. [`audio_subtype_availability.json`](evidence/audio_subtype_availability.json)에 공식 예시 ID와 집계를 남겼다.

[AudioSet](https://research.google.com/audioset/download.html)은 Bark 2,632건, [Whimper (dog)](https://research.google.com/audioset/dataset/whimper_dog.html) 1,826건, [Howl](https://research.google.com/audioset/dataset/howl.html) 838건의 주석을 제공한다. 공식 다운로드는 YouTube 구간 ID·라벨과 추출 특징이며 재사용 가능한 WAV 파일 모음이 아니다. Whimper (dog)의 공식 소규모 품질 점검은 5/10이었다. 이번에는 원본 음원을 확보·독립 검수하지 못해 세부 분류기를 학습하거나 정확도를 발표하지 않는다. YouTube 영상의 소리도 개체·가정·정확한 발성 시각의 정답이 아니다.

## 사용자 흐름과 실제 시연 DB

음원 업로드 화면에 공개 자료 출처 입력을 추가했다. 공개 시연 음원은 사용자 공통 학습 동의를 켤 수 없으며, 의견은 `demo_operator_opinion`으로 남아 실제 보호자 의견과 구분된다. 5초 분석 창 타임라인에서 후보 점수와 원본 구간 재생을 제공한다. 구간은 정확한 발성 시작·종료 시각으로 표시하지 않는다.

별도 로컬 DB `artifacts/presentation_20261011/demo.db`에서 브라우저로 외출 시작 → ESC-50 Dog 음원 선택·출처 표시·분석 → 구간 플레이어 재생 → 의견 → 귀가 → MCP 근거 요약을 확인했다. 추가 공개 자료 시연 세션에서는 기존 LSTM이 놓친 Dog 1건과 rain 1건을 입력했다. 둘 다 원본 SHA256과 시연용 출처를 기록했다. 2번째 세션은 표본 10초·영상 판단 불가 10초·에너지 기반 짖음 후보 6회다. **Dog 음원에서 LSTM은 놓쳤는데 에너지 후보는 6회**였으므로 두 신호를 같은 정확도로 해석하지 않는다.

세션 RAG 질문 3개를 실행했다. “무슨 소리가 있었어?”는 실제 저장된 관찰·시연 의견을 근거 ID와 함께 반환했고, “지난번과 달라?”는 같은 입력 방식 두 세션의 **저장 표본 분당 후보**만 비교했다. “보호자가 TV라고 확인한 것은?”은 공개 자료의 시연 담당자 의견을 보호자 확인으로 제시하지 않고 근거 부족을 반환했다. Gemini가 없는 이 별도 DB의 제공자는 `grounded-template`, 검색은 `mcp`였다. 상세 질문·응답·근거 ID는 [`presentation_demo_api.json`](evidence/presentation_demo_api.json)에 있다.

현재 브라우저 연결의 스크린샷 명령은 `Page.captureScreenshot` 시간초과가 재현됐고 전용 녹화 창 실행도 환경 정책에 막혔다. 따라서 `artifacts/presentation_20261011/petmind_public_data_walkthrough.mp4`에 **3분 51초 설명 영상**을 만들었다. 별도 시연 DB의 실제 API 응답을 Flutter 위젯으로 다시 렌더링한 화면, 비교 수치, 한국어 음성 설명과 원본 Dog 음원 5초가 들어 있다. 1920×1080 H.264/AAC 파일의 영상·음성 스트림 디코딩, 음성 신호와 두 시점 프레임을 확인했다. 이는 **실제 브라우저 클릭 화면 녹화가 아니다**. 브라우저에서는 접근성 트리로 클릭 흐름과 원본 플레이어 재생을 별도 확인했다. 발표에서는 설명 영상을 먼저 재생하고, 가능하면 같은 로컬 앱에서 짧은 실시간 클릭 시연을 이어간다.

영상 재생 순서는 문제·공개 자료 → 입력 출처 → 감지와 원본 재생 → 놓침·환경음 → 귀가 요약 → MCP 근거 → 동일 조건 성능 비교 → 남은 과제다. 화면 캡처 원본과 재구성에 쓴 API fixture도 `artifacts/presentation_20261011/`에 있으며 Git에는 포함되지 않는다. `python -m scripts.build_presentation_walkthrough`로 같은 자산에서 영상을 재생성할 수 있다.

최종 회귀검증: Python **106 passed**, Flutter **4 passed**, `flutter analyze` 오류 없음, 웹 릴리스 빌드 성공. 시연 DB는 실제 반려견·실제 보호자 데이터를 포함하지 않는다.

## 재현과 남은 작업

```powershell
python -m scripts.prepare_fsd50k_subset --split dev --official-partition val --per-class 60
python -m scripts.compare_audio_lstm
python -m scripts.audit_audio_subtypes
```

음원 준비에는 기존 ESC/FSD manifest와 원본이 필요하다. 화면 시연은 README의 API·Flutter 실행 명령을 사용하고, 별도 DB에는 `PETMIND_DATABASE_URL`을 지정한다. 시연 자료 스크립트는 브라우저로 첫 외출·Dog 업로드를 마친 뒤 `python -m scripts.prepare_presentation_demo`로 2번째 세션을 구성하며, 이미 두 세션이 있으면 검증 결과만 다시 기록한다.

다음 단계는 독립적인 가정 음향과 보호자 확인 자료를 확보해 개체·녹음 환경 단위로 학습/검증/평가를 나누는 것이다. 낑낑·하울링은 원본 이용 조건과 음원 단위 라벨을 검수한 뒤 별도 실험한다. 실제 사용자 모집 전에는 인증·사용자별 접근 제어가 필요하다.
