# 프로세스 정확성과 처리 비용 개선

2026-10-11. 전체 시스템의 정확도를 하나의 숫자로 합치지 않고 검색 누락, 설명 근거 보존, 집계 일치, 처리 비용을 각각 검증했다. 모델 자체의 실제 가정 감지 정확도가 향상됐다는 주장은 하지 않는다.

## 변경과 결과

| 영역 | 변경 전 | 변경 후 | 검증 범위 |
|---|---|---|---|
| 1,000건 요약 DB 조회 | 4,000회 | 4회 | SQLite 합성 관찰, 원본 조회를 500개씩 묶음 |
| 1,000건 집계 시간 중앙값 | 0.339925초 | 0.010890초 | 각 3회, 집계만 측정; 네트워크/LLM 제외 |
| 집계 결과 | 기준 결과 | JSON SHA256 동일 | 수치·근거·원본 상태 출력 전체 일치 |
| 기존 별도 질문 20개 | 직전 방식 15/20 | 20/20 | 이제 개발에 사용한 회귀 자료, 독립 평가 아님 |
| 수정 후 별도 질문 12개 | 초기 필터 3/12 | 10/12 | 같은 개발자 작성, 외부 사용자 정확도 아님 |
| 음원 모델 로딩+추론 | 중앙값 0.005358초 | 0.004630초 | 공개 5초 음원 1개·10회·CPU 2스레드, 약 13.6% 감소 |

첫 집계 호출은 기존 0.450438초, 수정 후 0.099036초였다. 중앙값은 예열 뒤 결과의 영향을 받는다. 전체 서비스가 31배 빨라졌다고 표현하면 안 된다. 음원 처리 개선도 한 파일의 로컬 반복 측정이며 전체 업로드 응답 시간과 다르다.

## 수정한 코드

- `services/outings.py`: 관찰마다 영상/음원 테이블을 여러 번 조회하던 부분을 일괄 조회로 변경했다. 만료·삭제·파일 유실 상태는 요청마다 확인하므로 상태 캐시에 의해 오래된 동의나 원본 상태를 돌려주지 않는다.
- `services/outing_retrieval.py`: 유니코드·대소문자·공백 정규화, 분석 분량 질문, TV/외부 소리 의견, 판단 불가 표현을 보강했다. 소리 후보를 설명할 때 영상 판단 불가 근거도 검색한다. 질문 의도별 근거와 최근 의견을 함께 제공한다.
- `services/outings.py`: Gemini가 질문에서 요구한 종류의 근거나 검색된 판단 불가 정보를 누락하면 근거 템플릿으로 대체한다. 실제 사용한 제공자/대체 여부는 계속 표시한다. 관련 없는 추가 근거까지 무조건 요구하지 않도록 실제 Gemini 검증 중 조정했다.
- `pet_monitor/audio_model_cache.py`, `routers/audio_clips.py`: 최대 2개 모델을 체크포인트 내용 기준으로 캐시한다. 개인 음원은 캐시하지 않는다. 같은 파일명·수정 시각이어도 내용이 바뀌면 새 모델을 읽는다.
- `test_outing_retrieval.py`, `test_audio_model_cache.py`: 검색 정규화, 근거 누락 방지, 모델 교체 캐시 무효화를 추가 검증했다.

## 실제 실행 결과

- 전체 Python **104개 테스트 통과 (13.90초)**. 의존성 검사 정상.
- 실제 Gemini 3건(세션 수치·하루 요약·보호자 의견)의 제공자·수치·인용 보존 검사 통과. `outing_gemini_verification.json`은 이번 재검증 결과다.
- 최신 로컬 API를 재시작해 세션 설명의 실제 MCP 검색, 필요한 근거 종류, 하루 중복 제외 집계를 확인했다. 음원 재업로드 관찰 #3은 집계에서 제외하고 표본 10초를 유지했다.
- 이번 변경은 백엔드·평가 스크립트이며 Flutter 코드는 수정하지 않았다. 이전 Flutter 4개 테스트·웹 빌드 결과를 새 UI 검증으로 재표기하지 않는다.

`docs/evidence/summary_before_optimization.json`, `summary_after_optimization.json`, `outing_retrieval_optimized.json`, `outing_retrieval_validation_v3.json`, `audio_cache_benchmark.json`, `process_optimization_runtime.json`에 측정·질문·출력 해시를 기록했다.

기존 20개 질문은 개선 작업에 사용했으므로 더 이상 별도 검증 세트로 해석하지 않는다. 새 12개 질문에서는 ‘몇 분이나 쌓였나요’, ‘얼마나 오래 봤나요’ 두 표현을 놓쳤다. 결과를 확인한 뒤 해당 질문에 맞춰 다시 수정하지 않았다.

## 남은 한계

오디오 LSTM의 FSD 외부 재현율 28.3%는 이번 변경으로 올라간 것이 아니다. 가중치·판정 임계값을 유지했다. 다음 감지 개선은 ESC뿐 아니라 다양한 생활 소음을 포함한 별도 검증 분할을 먼저 고정하고 진행해야 한다. 현재 테스트 점수를 보고 임계값을 낮추지 않는다. 사용자별 실제 정확도·케어 효과·Pi 처리 성능·동시 사용자 부하도 아직 검증하지 않았다.
