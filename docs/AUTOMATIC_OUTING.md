# 외출 시작과 자동 음성 분석 — 2026-10-12

## 사용자 흐름

외출·음원 메뉴의 기본 모드는 `자동 관찰 · Pi 마이크`다. 음성·사건 영상 저장에 동의하고 외출을 시작하면 DB에 수집 요청이 저장된다. Pi 에이전트가 요청을 수신하면 기존 FFmpeg 음성·사건 영상 프로그램을 실행한다. 음원을 직접 올릴 필요가 없다. 업로드 모드는 보조 입력으로 계속 제공한다.

서버는 요청 생성만으로 분석 중이라고 표시하지 않는다. Pi 연결 대기 → 장치 준비 → 실제 음원 분석 완료 후 분석 중으로 바뀐다. 모델 미준비·장치 단절도 구분한다. 요청 수락 및 heartbeat 응답의 서버 UTC 시각을 Pi의 요청 왕복 시각과 비교한다. 왕복 지연 또는 추정 시계 오차가 2초를 넘으면 `clock_mismatch`로 외출을 종료해 잘못된 시각의 기록을 막는다. 이는 현장 음성·영상 동기화 정확도 검증을 대신하지 않는다. 30초간 heartbeat가 없으면 연결 끊김으로 표시한다. Pi는 서버 연결 실패 시 수집 중지를 요청하고, 최대 150초 후 하위 프로세스까지 종료한다. 자동 재수집/오프라인 재전송은 구현하지 않았다. 단절 후 작업은 귀가 종료하고 새 외출을 시작한다.

귀가 버튼은 먼저 중지를 요청한다. 진행 중인 작업은 FFmpeg에 종료 입력을 보내 마지막 구간을 닫고, 음원 분석과 사건 영상 저장을 마친 뒤 외출을 종료한다. 기다리는 동안 UI는 종료 처리 중으로 표시한다. 기기가 대기 중이거나 이미 단절된 경우 서버에서 외출을 종료한다. 끝난 외출에 대한 후속 관찰 저장은 기존 API 검증으로 거부된다.

## 장비 연결 후 실행

현재 장비 연결·촬영 검증은 사용자 요청에 따라 보류했다. 자동 동작에는 사이트 외에 아래 Pi 프로그램이 계속 실행되어 있어야 한다. 전원 부팅 시 자동 실행 서비스 등록은 후속 작업이다.

1. Pi 테스트 폴더에 프로젝트 코드와 기존 `requirements-vision.txt`에 해당하는 실행 환경을 준비한다. FFmpeg, requests, soundfile이 필요하다. Pi는 캡처를 수행하며 LSTM은 PC API에서 추론한다.
2. 실제 장치를 확인하고 Pi에 FFmpeg 입력 인수 JSON을 만든다. 예: `["-f","v4l2","-i","/dev/video0","-f","alsa","-i","hw:1,0"]`. 장치 번호는 예시이며 직접 확인해야 한다.
3. PC에서 SSH 터널을 유지한다:

```powershell
ssh -N -R 127.0.0.1:18010:127.0.0.1:8010 -L 18081:127.0.0.1:18081 -o ExitOnForwardFailure=yes raspberrypi-ai
```

4. Pi 프로젝트 루트에서 실행한다. `pet-id`는 사이트에서 선택한 반려견 ID와 같아야 한다.

```sh
python -m scripts.pi_outing_agent --pet-id demo-dog --input-args-file /absolute/path/devices.json --video-map 0:v:0 --audio-map 1:a:0
```

5. PC `.env`의 `PETMIND_CAMERA_SNAPSHOT_URL=http://127.0.0.1:18081/snapshot.jpg` 설정 후 API를 재시작한다. 사이트에서 저장에 동의하고 외출을 시작한다.

## 카메라 공유와 한계

자동 수집 에이전트와 기존 `pi_camera_preview.py`를 동시에 실행하지 않는다. 에이전트가 웹캠을 단독으로 열고, 완료된 약 5초 구간에서 최근 프레임을 추출해 미리보기에 제공한다. 따라서 외출 중에는 약 5초 단위의 지연된 장면이며 2fps 실시간 스트림이 아니다. 외출 종료·수집 중지 시 미리보기도 멈춘다. 외출 밖 상시 라이브와 더 낮은 지연은 후속 개선이다. 프레임이 12초 이상 갱신되지 않으면 미리보기는 503을 반환한다.

음성은 기본 7일 보관, 공통 학습 동의는 false다. 자동 외출 시작 시의 저장 동의 시각은 외출 기록에 남긴다. 사건 전후 장면만 영속 저장하고 연속 영상 버퍼는 임시 폴더에 둔다. RAG와 요약은 외출 전체 시간에서 분석 표본을 뺀 시간을 관찰 공백으로 설명하며, 조용했던 시간으로 간주하지 않는다. 귀가 요약은 에너지 기반 후보 횟수와 LSTM의 개 소리 후보 분석 창 수를 따로 표시한다. 실제 동기화·장시간 성능·장치 재연결은 미검증이다.

## 검증 및 변경 파일

- `database.py`, `routers/capture.py`, `routers/outings.py`, `main.py`: 기존 DB를 유지하면서 새 capture_jobs 테이블을 생성한다. 동의·소유권·중복 수신 방지·대기 취소·귀가 완료·단절을 검증했다.
- `monitor_audio_events.py`, `pi_outing_agent.py`: 중지 파일, 진행 상태, 프레임 공유, Pi 수신/heartbeat/프로세스 정리를 추가했다.
- `outings_panel.dart`, `audio_panel.dart`, `main.dart`: 기본 자동 모드, 저장 동의, 상태 갱신, 홈 상태, 음원 의견 검토를 연결했다.
- `services/outings.py`: RAG 근거에 미분석 시간과 해석 제한을 추가했다.
- `test_capture.py`, `outings_panel_test.dart`: 수집 수명주기와 동의 후 대기 UI를 검증했다.
- 전체 Python 131개, Flutter 21개 테스트 통과. 웹 릴리스 빌드 완료. 기존 기록·업로드 API 호환성을 유지했다.
- 별도 검증 DB에서 30초 공개 음원+테스트 패턴을 입력했다. 중지 파일을 전달한 실행은 종료 코드 0, 분석 기록 5개, LSTM 감지 구간 1개, 사건 영상 15초를 생성했다. 프레임 공유 JPEG와 모델 준비 상태도 확인했다. 실제 Pi 영상이나 전체 agent 실장비 왕복 시험은 아니다.

단일 가정·로컬/SSH 시제품이다. API는 비로컬 접속과 외부 웹 Origin을 거부하지만 사용자·장치 인증을 구현한 것은 아니다. 외부 공개 전에는 장치 인증과 사용자별 접근 제어가 필요하다. 프로세스 소유 토큰은 중복 실행 방지용이며 사용자 인증을 대체하지 않는다.
