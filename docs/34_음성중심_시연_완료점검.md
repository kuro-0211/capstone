# PetMind 음성 중심 시연과 완료 점검

기준일: 2026-10-11. 이 문서는 당시 시연 상태의 기록이다. 최신 브라우저 확인·출처 구분과 회귀 결과는 [파트 38](38_자체피드백_안정성_출처_사용성.md)을 따른다.

## 발표에서 설명할 핵심

반려견의 소리와 움직임만으로 감정·질환을 단정하지 않는다. PetMind는 외출 중 관찰 신호와 보호자 의견을 반려견별로 저장하고, 과거 기록과 원본 근거를 찾아 보호자가 케어 제안을 검토하도록 돕는다. 급식기와 추가 센서는 제외한다. 웹캠의 역할은 근거 장면 확인이며 음성 분석은 공개 자료에서 먼저 검증한다.

기존 FastAPI·SQLite·Flutter·MCP 구조를 유지했다. 별도 오디오 LSTM은 실험 점수로 제공하고 에너지 이벤트와 구분한다. RAG는 수치를 계산하지 않는다. 서버가 중복 구간을 제외하고 집계한 사실 중 질문에 맞는 근거를 선택하며, Gemini 응답도 허용된 근거 ID만 사용한다. 보호자 의견은 모델의 확정 정답과 분리한다.

## 실행

저장소 루트에서 기존 README의 환경 구성을 먼저 수행한다. 다음 명령은 저장소 안에 `.venv`를 만든 환경 기준이다. 원본 음원·체크포인트·개인 DB·키는 저장소에 포함하지 않는다.

```powershell
# 터미널 1: 로컬 백엔드
.\.venv\Scripts\python.exe -m uvicorn petmind.backend.main:app --host 127.0.0.1 --port 8010

# 터미널 2: Flutter 화면
cd petmind_app
flutter run -d chrome --web-port 8021 --dart-define=PETMIND_API_BASE=http://127.0.0.1:8010
```

검증 당시 개발 PC는 별도 시연 DB와 API 8011 / 웹 8022를 사용했다. 기본 API 8010과 혼동하지 않는다. `PETMIND_DATABASE_URL`을 지정하면 API와 MCP 하위 프로세스가 같은 DB를 사용한다. Gemini는 로컬 `.env`의 `GEMINI_API_KEY`와 `PETMIND_LLM_PROVIDER=gemini`를 사용한다. 키 없이 규칙 제공자로 실행할 수 있고 화면에서 실제 제공자를 확인한다.

오디오 LSTM이 없으면 모델 미준비 상태를 표시한다. 실험 모델 준비는 파트 33의 공개 데이터 명령을 따른다. 공개 자료 다운로드·학습은 용량과 시간이 필요하므로 발표 직전에 실행하지 않는다. 준비된 영상 시연에는 `artifacts/media/manifest.json`과 재분석 결과 `artifacts/video_analysis.json`이 필요하다.

## 5분 시연 순서

1. 프로젝트 목적과 현재 입력 출처를 설명한다. 실시간 녹음이나 실제 감정 진단이라고 소개하지 않는다.
2. **사용자 음원** 모드로 외출을 시작한다. 30초 이하 WAV를 선택하고 개인 저장에 동의한다. 학습 참여는 별도 선택임을 보여준다.
3. 분석 결과와 원본을 확인한다. 보호자 의견을 ‘반려견 소리 / TV·외부 소리 / 기타 / 판단 어려움’ 중 선택하고 메모를 남긴다. 공개 음원 시연이면 실제 보호자 기록이 아님을 명시한다.
4. 외출을 종료하고 근거 기반 요약을 연다. 표본 시간·영상 판단 불가·소리 후보 수와 보호자 의견을 확인한다. 음원만 분석했을 때 영상 판단 불가는 정상이며 음성 모델 실패를 뜻하지 않는다.
5. 근거 링크로 원본을 재생한다. 팝업 안의 버튼이 반응하지 않으면 **원본 플레이어 새 탭에서 열기**를 사용한다. 연결 파일이 없거나 삭제됐으면 원본 없음으로 안내한다.
6. **하루 근거 설명**과 이전 세션 비교를 확인한다. 같은 입력 방식의 기록이 부족하면 비교 불가로 표시한다. 저장 표본의 분당 소리 후보 비교를 전체 외출 상태나 케어 효과로 해석하지 않는다.

영상 보조 시연은 별도 외출에서 **준비된 영상·음원**을 선택한 뒤 공개 입력 분석을 실행한다. 사용자 음원을 영상 모드 세션에 잘못 넣으면 거부된다. DAVIS 이미지 시퀀스의 5fps 재구성과 별도 ESC 음원의 결합은 동시 녹화가 아니다.

## 발표에 사용할 수치

| 비교 | 결과 | 해석 한계 |
|---|---|---|
| ESC 최종 평가 오디오 LSTM | F1 62.5%, 개 소리 5/8 감지 | 양성 8개뿐, 실제 가정 정확도 아님 |
| FSD 평가 120개 기존 LSTM | F1 43.6%, 개 소리 17/60 감지, 비개 오탐 1/60 | 놓치는 소리가 많음 |
| FSD 240개 추가 학습 | 검증 성능 개선 없음, 기존 모델 유지 | 데이터 양 증가만으로 해결되지 않음 |
| CLAP 비교 | FSD F1 83.5%, 개 소리 43/60 감지 | 사전학습 중복 가능성, 운영 채택 안 함 |
| CPU 실행 비용 | 5초 음원 처리 중앙값 LSTM 0.00462초 / CLAP 0.12714초 | 이 PC 2스레드·3음원 각 3회, Pi/서버 부하 평가 아님 |
| RAG 개발 회귀 질문 | 근거 포함 8/16→16/16 | 구현에 사용한 개발자 질문 |
| RAG 별도 질문 | 근거 포함 8/20→15/20 | 같은 개발자가 작성, 표현 다양성 실패 5건 |
| 실제 Gemini 연동 | 가상 기록 3건 모두 근거·수치 보존 | 일반적인 응답 정확도 지표 아님 |

## 사용자 데이터로 이어갈 단계

개인 기록 저장 동의와 공통 모델 학습 동의를 분리한다. 보호자 상황 의견을 음향 라벨로 자동 변환하지 않는다. TV의 개 소리는 음향 분류상 dog일 수 있다. 학습 참여·유효한 원본·보관 기간·독립 검수를 통과한 자료만 학습 목록으로 내보낸다. 의견 수정·동의 철회·원본 삭제 후 기존 목록을 다시 검증한다. 이미 학습한 모델에서의 역학습은 구현하지 않았다.

실제 데이터가 생기면 감지된 사건뿐 아니라 일반 구간과 놓친 사례도 모은다. 공통 모델은 가정/반려견 단위로, 개인화는 과거와 이후 시점으로 나눠 평가한다. 현재 `pet_id`는 인증이 아니므로 외부 사용자 모집·공개 서비스 전에 인증과 사용자별 접근 제어를 추가해야 한다.

## 복구 순서

- 화면이 연결되지 않으면 API 포트와 `PETMIND_API_BASE`를 대조한다. 환경 변경 뒤 서버를 재시작하고 웹을 다시 빌드한다.
- 같은 반려견의 활성 외출이 있으면 새 외출 대신 기존 외출을 종료한다.
- 음원은 WAV·최대 30초·최대 12MB 조건을 확인한다. 보관 만료 후에는 원본이 없어도 남은 집계·의견 기록을 조회할 수 있다.
- 영상 해시가 바뀌면 분석을 다시 실행한다. 새 파일에 기존 분석 결과를 붙이지 않는다.
- Gemini 실패 시 대체 제공자가 표시된다. 대체 응답을 실제 Gemini 성공으로 기록하지 않는다.
- 사용자 DB를 초기화하거나 원본 파일을 일괄 삭제하는 방식으로 복구하지 않는다.
