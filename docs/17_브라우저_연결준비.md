# 파트 17 — 브라우저 연결 준비와 남은 재시작

검증일: 2026-10-11. 사용자 요청: 브라우저 연결도 직접 준비.

## 확인한 원인

- `C:/Users/kuro/.codex/config.toml`의 `browser@openai-bundled` enabled가 false였다.
- 번들 Browser 패키지는 `26.1007.21434` 버전으로 로컬에 존재한다.
- 설치된 지원 브라우저로 Microsoft Edge가 확인됐다. 기본 HTTP 브라우저는 Whale이며 지원 목록에서 확인되지 않았다.
- 공식 Chrome 연결 진단에서 OpenAI native messaging host의 등록과 manifest가 없는 것을 확인했다.
- 현재 브라우저 제어 surfaces는 비어 있다.

## 완료한 준비

공식 문서의 enabled 설정 방식으로 번들 Browser만 true로 변경했다. TOML 전체 구조를 비교해 그 플래그 외 설정이 동일함을 확인했다. 다른 앱 권한·사이트 권한·확장 설치·브라우저 프로필을 수정하지 않았다.

원래 값은 false였으므로 되돌릴 때 `[plugins."browser@openai-bundled"]`의 enabled만 false로 바꾸면 된다. 전체 설정 파일과 비밀값은 프로젝트에 복사하지 않았다.

## 실제 연결을 막는 상태

활성화 후에도 현재 실행 세션의 연결 모듈이 `browser/26.1002.52244/scripts/browser-service.mjs`라는 이미 없는 구버전 파일을 참조한다. 연결 런타임 초기화 전후 두 번 모두 같은 Cannot find module 오류가 발생했다. 현재 최신 파일을 오래된 버전 경로로 위장해서 복사하지 않았다.

따라서 **Browser 활성화 준비는 완료, 실제 브라우저 연결은 미완료**다. 현재 세션의 모듈 참조를 갱신하려면 Codex 앱을 완전히 종료하고 다시 열어야 한다. 앱 재시작 후 이 채팅의 목표를 이어서 진행한다. 필요하면 [Browser 설정](codex://settings/browser-use)에서 활성화 상태를 확인한다.

## 재시작 후 순서

차단 감사 결과: 연속 세 번의 목표 턴에서 같은 구버전 서비스 파일 누락을 재확인했다. 현재 버전 서비스 파일은 존재하며 Browser enabled=true, backend/web HTTP 200이 확인됐다. 현재 세션의 연결 모듈을 지원되는 방법으로 실행할 수 없어 목표 상태를 blocked로 기록한다. 앱 재시작 후 목표를 재개하며, 브라우저 클릭·녹화를 완료로 주장하지 않는다.

후속 재확인: 일반 실행 환경의 단순 응답은 정상이나, 실제 `setupBrowserRuntime` 호출은 동일한 구버전 `26.1002.52244` 파일 누락으로 실패했다. 단순 실행 성공을 브라우저 연결 성공으로 판단하면 안 된다. Browser 활성화는 유지되어 있고 API와 화면 HTTP 서버는 정상이다. 실제 브라우저 연결·시연은 여전히 미완료다.

1. Browser 설정과 연결 목록을 확인한다. 내장 브라우저는 별도 외부 브라우저 확장 없이 로컬 화면을 여는 경로로 우선 검증한다.
2. `http://127.0.0.1:8010/health`, `http://127.0.0.1:8020`을 확인한다. 프로세스가 종료됐으면 README의 백엔드·가상 장치·웹 서버 명령으로 다시 실행한다.
3. 실제 브라우저에서 휴식·반복 신호·공개 입력을 클릭하고 Gemini 근거·승인·실행 완료·반려견 분리를 확인한다.
4. 실제 브라우저 화면 캡처·시연 녹화를 확보하고 파트별 결과를 갱신한다.
