# 파트 28 — 추적 ID 재연결 개선

작성일: 2026-10-11

## 문제와 수정

InterPet4D 보류견 영상 두 개에서 YOLO가 개를 계속 검출해도 ByteTrack ID가 바뀌면 기존 코드가 첫 ID만 선택했다. 첫 평가에서 dog08은 123프레임 중 29프레임, dog10은 133프레임 중 29프레임만 선택됐다. 이 데이터는 5fps로 표본화되며 LSTM은 최소 40개 관찰점이 있어야 결과를 낸다.

선택기(`pet_monitor/tracking.py`)를 추가해 짧은 ID 변경은 단일 검출 대상일 때만 중심 위치, 박스 크기, HSV 외형 분포로 연결한다. 검출이 오래 끊기거나 여러 마리가 겹치거나 큰 위치 점프가 생기면 기존 입력 구간을 버린다. 단일 대상이 3프레임 연속 안정적으로 보이면 새 시간 구간으로 재시작한다. 이 연결은 ID를 이어 붙이는 휴리스틱이며 개체 동일성을 증명하지 않는다.

추가로 짧은 공백 연결에서 IoU(박스 겹침)를 필수로 두지 않도록 수정했다. 움직임 때문에 박스가 겹치지 않아도 위치 이동량 15% 이하, 크기 변화 0.5~2배, 외형 유사도 조건을 만족하면 연결 가능하다. 테스트에 박스가 겹치지 않는 재연결과 서로 다른 외형 거부 사례를 넣었다.

## 실제 영상 검증

같은 원본과 모델, 동일한 5fps 표본으로 재실행했다. ID 재획득 구현 전과 후를 비교하면 선택 추적 프레임이 늘고 다른 ID만 보이는 프레임이 줄었다.

| 영상 | 선택 추적 프레임: 이전 → 수정 | 다른 ID만 검출: 이전 → 수정 | LSTM 결과 |
|---|---:|---:|---|
| dog08, 24.55초 | 29/123 → 68/123 | 57 → 18 | 전체 `unknown` |
| dog10, 26.44초 | 29/133 → 62/133 | 66 → 33 | 전체 `unknown` |

두 영상 모두 선택 프레임은 늘었지만 40프레임 연속 구간을 만들지 못해 예측 coverage는 여전히 0%다. 따라서 이 작업은 추적 지속성을 개선했으며, 행동 분류나 실제 정확도를 개선했다고 말할 근거는 없다. 원본 설명에는 행동 문장이 있지만 프레임별 시각 라벨이 아니므로 정확도 계산에 사용하지 않았다. 보수적인 추적 정책이 여러 짧은 구간을 만든 원인에는 검출 누락, ego 카메라 이동, 대상의 큰 화면상 이동이 남아 있다.

## 확인 결과와 한계

- `tests/test_tracking.py`: 5 passed.
- ID 재연결 단계 전체 Python 테스트: 62 passed. 아래 추적 빈도·시간 coverage 수정 후 63 passed.
- 실제 보류견 영상 두 편을 수정 후 v2·v3로 재처리. 기록: [InterPet 영상 추적 평가](evidence/interpet_video_evaluation.json).
- 현재 운영 모델 v2는 유지했다. 후보 v3도 이 영상들에서 coverage 0%였으며, 동작 분류 정답 라벨이 없다.
- 다음에는 고정 카메라 또는 영상 안정화 조건을 비교하고, 동일 개체/행동 구간을 사람이 시간별로 라벨링한 영상으로 추적 ID 오류와 분류 정확도를 따로 평가해야 한다.

## 추가 진단: `unknown`이 계속 나오는 이유

사용자 피드백에 따라 약 60fps 원본에서 추적기도 5fps만 받던 처리 방식을 바꿨다. ByteTrack에는 약 15fps로 중간 프레임을 전달하고, 출력 영상과 LSTM 판정은 기존 약 5fps를 유지한다. LSTM이 받는 관찰은 실제 검출 시각을 보존한다. 입력이 더 촘촘해진 만큼 10초 구간의 관찰 비율은 원시 검출 개수가 아니라 50개 시간 위치 중 관찰점에 가까운 위치의 수로 계산한다. 점 몇 개가 한 시점에 몰려 80% coverage로 잘못 세어지지 않도록 했다.

| 영상 | 5fps 추적 선택 프레임 | 15fps 추적 선택 프레임 | 최장 연속 구간 | 출력 |
|---|---:|---:|---:|---|
| InterPet dog08 | 68/123 | 81/123 | 3.61초 | 전체 `unknown` |
| InterPet dog10 | 62/133 | 85/133 | 6.94초 | 전체 `unknown` |

추적률은 다시 올랐지만 LSTM에는 9.8초 입력창과 최소 80% 시간 coverage가 필요하다. 두 원본의 최장 연속 구간은 이에 못 미친다. 임계값을 내리거나 짧은 좌표를 10초로 늘려 예측하는 방식은 현 체크포인트의 학습 조건과 달라 실제 행동 판정으로 채택하지 않았다.

별도로 TigDog 공개 원본의 첫 15초(`video_id=8`, 기존 평가의 이동 라벨 10초 구간 포함)를 영상 파이프라인에 넣었다. 149개 관찰점이 이어진 9.88초 구간이 한 번 있었고, 기본 v2 모델이 `moving`을 0.20초 출력했다. 나머지 14.81초는 `unknown`이었다. 이 구간은 기존 개발 자료를 다시 사용한 시연 점검이며 새 독립 정확도 평가가 아니다. 출력 파일은 로컬 `artifacts/video_demo/tigdog_first15s_v2/`에 있으며 원본과 출력 영상은 Git에서 제외한다.

추가 시간 coverage 테스트와 전체 Python 테스트 **63 passed**. 기본 체크포인트는 v2로 유지한다. 실제 시연의 준비 시간을 줄이려면 3~5초 입력에 맞춰 별도 모델을 학습하고, 이동·비이동을 포함한 독립 영상에서 정확도와 오탐을 검증해야 한다. 특히 왕복 같은 시간 패턴은 짧은 입력에서 판정할 수 있는지 별도 확인이 필요하다.
