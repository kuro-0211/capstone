# 생활 소음 속 개 짖음 소리 후보: 웹 UI 시연 전 검증

검증일: 2026-10-12. 기존 `artifacts/audio_lstm/esc50_lstm.pt`와 판정 기준 0.9를 고정했다. 자료는 이미 내려받아 기존 개발 비교에 사용했던 [FSD50K](https://zenodo.org/records/4060432)의 공식 `eval` 분할이다. 따라서 아래 수치는 **새 독립 정확도 평가가 아니라 시연 적합성 점검**이다.

## 실제 공개 음원

로컬 `eval_subset/manifest.json`의 원본 ID·SHA-256·라벨을 확인했다. `Dog`와 `Bark`가 함께 있고, 문·말소리·벨·대화·풍경 소리 중 하나가 함께 표기된 **6개를 전부** 검사했다. 같은 부분집합에서 `Dog`가 없고 해당 생활 소음이 표기된 **23개도 전부** 검사했다.

| 구분 | 결과 |
|---|---:|
| 짖음+생활 소음 라벨: 감지 | **0/6** |
| 짖음 없음+생활 소음 라벨: 오탐 | **0/23** |
| 운영 판정 기준 | **0.9** |

첫 6개의 모델 점수는 0.4861, 0.6475, 0.0480, 0.0197, 0.0609, 0.0334였다. `Dog`와 `Bark`는 **음원 단위 라벨**이므로, 이 자료만으로 짖음이 정확히 언제 들리는지 또는 생활 소음과 실제로 같은 순간에 겹치는지는 증명할 수 없다. 이 음원이 집 안에서 녹음됐다는 뜻도 아니다.

## 별도 혼합 시연 음원

FSD50K의 짖음 음원 `15791.wav` 첫 5초에 문 `195579.wav`, 식기 `38957.wav`, 사람 말소리 `400092.wav`를 각각 섞었다. 생활 소음의 RMS는 짖음 RMS의 40%로 고정했고, 필요한 경우 최대 진폭만 제한했다. 원본과 조합·해시는 `artifacts/household_bark_20261012/mixture_results.json`에 남겼다. 세 파일은 **실제 가정 녹음이 아닌 공개 자료의 합성 혼합**이다.

| 혼합 조건 | 모델 점수 | 판정 |
|---|---:|---|
| 짖음+문 | 0.838 | 놓침 |
| 짖음+식기 | 0.123 | 놓침 |
| 짖음+말소리 | 0.104 | 놓침 |

## 결정

이 결과로는 “생활 소음 속 짖음을 잘 찾는다”는 발표 시연을 만들 수 없다. 현재 웹 UI에 성공 사례로 올리거나 결과 영상을 녹화하는 조건을 충족하지 못했다. 모델 교체와 판정 기준 변경도 이 평가 자료를 보고 곧바로 하지 않는다.

다음에는 **학습·검증 자료에서** 생활 소음을 섞어 모델을 개선하고 판정 기준을 정한다. 이 실험에 사용한 FSD50K `eval` 파일은 최종 사후 확인에만 둔다. 새 출처의 짖음·비짖음 혼합 원본을 별도로 확보해 감지율과 오탐을 함께 확인한 뒤 UI 시연에 올린다. 화면에는 공개 자료 출처와 “시연용”을 표시하고, RAG 설명은 모델 결과와 보호자 의견을 구분한다.

재현: `python -m scripts.check_household_bark_demo` 및 `python -m scripts.make_household_bark_cases`. 상세 원본별 결과는 Git 제외 `artifacts/household_bark_20261012/`에 있다. 전체 Python 회귀 테스트 **139개 통과**.

## 2026-10-12 · 혼합 자료 학습 후보

위 결과를 토대로 `scripts.train_household_bark_lstm`에서 **기존 LSTM을 출발점으로** FSD50K 공식 학습 분할의 `Bark` 음원 32개와 생활 소음 음원 28개를 사용했다. 짖음 원본마다 생활 소음의 세기를 세 수준으로 바꿔 **96개 혼합 학습 자료**를 생성했다. 학습 분할의 기존 음원 240개도 함께 사용했다. 음원 전체에 붙은 약한 `Bark` 라벨을 5초 창마다 정확한 정답처럼 취급하지 않도록, 음원 안의 최고 점수를 학습하는 기존 MIL 방식을 유지했다. 학습 원본과 검증 원본의 ID·해시는 서로 다르며 혼합본도 원본과 같은 분할에만 둔다.

모델 선택에는 FSD50K 공식 검증 분할의 짖음 42개와 생활 소음 15개를 사용했다. 짖음 파일에 **검증 분할의 소음만** 섞어 기존 모델과 비교했다. 판정 기준 0.9를 고정하고 6차례 학습 결과 중 검증 점수가 가장 높은 3차례째 후보를 선택했다.

| 자료 | 기존 모델 | 혼합 학습 후보 | 해석 |
|---|---:|---:|---|
| FSD 검증 혼합: 짖음 감지 | 3/42 | **10/42** | 개선됐지만 32개는 여전히 놓침 |
| FSD 검증 혼합: 생활 소음 오탐 | 0/15 | 0/15 | 이 작은 검증 집합에서는 유지 |
| FSD 검증 전체 F1 | 43.8% | **69.2%** | `Dog` 음원 단위 분류 |
| ESC 검증 F1 | **88.9%** | 66.7% | 기존 자료의 오탐 증가 |

후보를 고정한 뒤 이미 열어 본 평가 자료에 적용했다. 이는 **독립적인 새 성능 증거가 아닌 사후 점검**이다.

| 사후 점검 | 기존 모델 | 혼합 학습 후보 |
|---|---:|---:|
| 생활 소음과 함께 표기된 `Bark`: 감지 | 0/6 | 1/6 |
| 같은 집합의 생활 소음만 있는 파일: 오탐 | 0/23 | 0/23 |
| 별도 공개 음원 합성 혼합: 감지 | 0/3 | 1/3 |
| FSD 평가 전체 F1 | 43.6% | 51.8% |
| FSD 평가 비개 소리 오탐 | 1/60 | 3/60 |
| ESC 평가 전체 F1 | **62.5%** | 52.2% |
| ESC 평가 비개 소리 오탐 | 3/392 | 9/392 |

**결정:** 후보 체크포인트는 `artifacts/audio_lstm/household_bark_candidate.pt`에만 보관하고 웹 UI의 기본 체크포인트는 유지한다. 생활 소음 속 짖음을 1/6건밖에 찾지 못했고 다른 자료의 오탐이 늘었기 때문이다. 판정 기준을 사후 평가 점수에 맞춰 변경하지 않았다. 이 단계에서 성공 시연 영상을 촬영하면 전체 성능을 오해하기 쉽다. 실제로 집 안에서 녹음되고 짖음 시각까지 검수된 자료를 추가 확보한 뒤 다시 검증해야 한다.

전체 결과와 원본별 점수: Git 제외 `artifacts/household_bark_20261012/training_comparison.json`. 후보는 운영에 승격하지 않았다.
