# 파트 13 — 가상 장치 동시 실행·재전송 보강

검증일: 2026-10-11

## 문제와 수정

기존 에이전트는 캐시를 SELECT한 뒤 INSERT해 두 에이전트가 동시에 같은 명령을 처리하면 UNIQUE 오류로 종료될 수 있었다. `petmind/device_agent.py`에서 SQLite의 원자적 `INSERT OR IGNORE`로 변경하고 최초 저장 결과를 다시 읽어 응답한다. 최초 처리와 재전송은 `replayed_ack`로 구분한다.

이 기능은 같은 SQLite 캐시를 공유하는 로컬 가상 실행의 중복 방지다. 서로 다른 캐시나 실장비의 분산 실행에서도 물리 음악을 정확히 한 번 재생한다고 주장하지 않는다.

## 검증

- `tests/test_device_agent.py`: barrier와 실제 SQLite 파일로 동시 호출을 재현했다. 새 기록 1개·재전송 1개, 저장 행 1개, 동일 결과를 확인했다.
- 재전송에서 다른 outcome을 지정해도 최초 저장 결과를 유지하는 테스트 통과.
- 전체 Python 기능 테스트 **40 passed**.
- 실행 중인 가상 장치를 새 코드로 재시작했다.
- 실제 HTTP 3개 시나리오 재실행: 관찰 6건, 제안 3건, MCP 성공 3건, 가상 음악 완료 2건, 실패 0건.
