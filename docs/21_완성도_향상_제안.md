# 다음 개발 단계 — LSTM·RAG 완성도 향상 제안

작성일: 2026-10-11. 이 문서는 사용자 요청에 따라 먼저 검토할 제안이며, 아래 개선을 새로 구현하거나 검증했다는 보고서가 아니다.

## 현재 판단

전체 분석·DB·MCP·Gemini·Flutter·가상 장치·Pi 왕복은 연결했다. Python 기능 테스트 44개 통과는 소프트웨어 동작 검증이며 실제 행동 정확도·검색 품질 성적과 구분한다.

LSTM은 합성 궤적과 중심 좌표·속도 4개 특징을 학습한 초기 모델이다. 실제 행동 정답이 없고, 공개 입력의 원본 녹화 시간도 미검증이다. 정상 추적 입력에는 softmax 최고 클래스를 반환하며 낮은 확신도에 의한 unknown 거부는 아직 없다. 정지 궤적만으로 앉기·눕기·잠을 구분할 수 없다.

RAG는 같은 반려견·기간 필터, 키워드/라벨 관련도, SQL 통계, 실제 Gemini·인용 검증을 갖췄다. 검색 점수가 0인 기록도 최근순으로 반환한다. 한국어 의미 검색, 질문의 기간·의도 해석, 답변 내용과 근거의 일치 평가가 약하다. 인용 ID 유효성만으로 모든 서술의 사실 정확도가 보장되지는 않는다.

## LSTM 우선 개선

1. 원본 FPS·관찰 시각이 확인되는 고정 카메라 영상과 사람이 판정한 궤적 라벨을 확보한다. 초기 작업 목표는 정지·이동·회전·왕복의 짧은 검증 클립 40~80개다. 이는 수집 착수 목표이며 충분한 학습량을 보장하는 숫자가 아니다. 확보 어려운 클래스는 부족함을 명시한다.
2. 촬영 영상·세션·가능하면 반려견 단위로 학습/검증/테스트를 분리한다. 같은 영상의 겹치는 구간이 서로 다른 분할에 섞이지 않도록 한다.
3. 크기 변화·이동량·가속도·방향 전환·추적 품질을 추가한다. 자세 의미가 필요하면 영상 외형 특징과 별도 라벨이 필요하다. 기존 4종 궤적 분류부터 검증한다.
4. 낮은 확신도·추적 불량의 unknown 처리와 분류 결과 안정화를 추가한다. 임계값은 검증 데이터로 정한다. softmax 값이 실제 신뢰도를 보장한다고 표현하지 않는다.
5. 실제 분리 평가의 클래스별 F1·혼동행렬·unknown 비율과 현재 규칙 분류기 비교를 기록한다. 모델·학습 데이터·특징 버전을 보관한다.

## RAG 우선 개선

1. 질문의 기간·관찰/통계/케어 이력 목적을 파악해 해당 읽기 전용 MCP 도구와 필터를 적용한다. '어제 밤', '최근 한 달', '음악 후 변화'를 고정 7일 검색으로 대체하지 않는다. 모호한 기간은 명확히 표시한다.
2. 검색 대상에 관찰뿐 아니라 관련 케어·실행·보호자 의견을 포함하고, 관련도 없는 기록을 구분한다. 숫자는 계속 SQL/검증 코드에서 계산한다.
3. 키워드/라벨과 텍스트 임베딩을 함께 사용한다. 기존 Gemini embedding API를 활용하고 SQLite에 벡터를 저장해 NumPy 유사도 검색으로 시작할 수 있다. 별도 벡터 DB는 현재 규모에서 먼저 도입하지 않는다. 반려견·시각·기간 필터는 의미 검색보다 먼저 강제한다.
4. 사실·계산 값·인용·제안·근거 부족을 구분한다. 답변의 숫자와 관찰/집계 값을 검증하고, 연관성이 낮으면 근거 부족으로 응답한다.
5. 한국어 질문 20~30개와 기대 관련 기록을 만들어 현재 검색 대비 상위 5개 검색 적중, 인용 정확성, 근거 없음 처리와 지연 시간을 비교한다. 질문 수는 초기 평가 목표이며 일반 성능을 입증하는 표본 수는 아니다.

## 추가 후보

- 음성의 실제 짖음/비짖음 분류: 공개 대조 음원 15개 중 3개 오탐이 있다. 이전 로컬의 MFCC·RandomForest 특징/학습 코드를 검토해 재사용할 수 있다. 기존 감정 라벨을 그대로 사용하는 대신 먼저 소리 종류 분류를 검증한다.
- 카메라·마이크가 있을 때 Pi 실제 입력 수집: 세션·원본 시간축·입력 출처를 저장하고 PC에서 분석한다. 센서 보유·동작 확인과 데이터 수집 시간은 별도다.
- 라벨링/오탐 검토 화면: 클립·예측·사람 판정·확인 메모를 연결해 평가용 데이터로 내보낸다. 기존 단순 보호자 피드백 화면을 확장한다.
- Pi heartbeat·실행 주체 표시·재연결: Pi 연결 상태, PC/Pi 처리 위치, 요청·수신·완료를 시연에서 확인한다. 실제 네트워크 단절 복구를 검증한다.
- 모델/검색 품질 비교 화면과 버전 기록: 현재 운영 처리 수치 화면을 실제 모델·검색 성능 비교로 확장한다.
- 전체 실제 시연 녹화: 입력→LSTM→검색 근거→Gemini→승인→Pi 응답을 한 흐름으로 확보한다.

## 추천 작업 순서와 추정 시간

| 순서 | 작업 | 개발·검증 추정 |
|---|---|---|
| 1 | LSTM·RAG 평가 기준과 초기 정답 세트 | 2~4시간, 실제 자료 확보 별도 |
| 2 | RAG 기간/의도·관련도 개선과 임베딩 검색 | 4~8시간 |
| 3 | LSTM 입력 특징·unknown 처리·안정화 | 3~5시간 |
| 4 | 실제 영상 라벨링·재학습·분리 평가 | 1~2일 이상, 데이터 확보 조건에 따라 증가 |
| 5 | 음성 분류기 초기 재사용·대조 평가 | 4~8시간 + 필요한 라벨링 |
| 6 | Pi 실제 입력·heartbeat·장애 복구 | 6~12시간, 장비 동작이 확인된 조건 |
| 7 | 성능 비교 화면·전체 시연 녹화 | 3~5시간, 브라우저 연결 완료 조건 |

추정치는 보장 시간이 아니다. 단기에는 RAG 평가/검색과 LSTM 불확실성 처리를 진행하고, 실제 데이터 확보를 함께 시작한다. 합성 성적을 실제 정확도로 발표하지 않는다. 급식기는 제외한다.
