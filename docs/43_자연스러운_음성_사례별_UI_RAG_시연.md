# 자연스러운 AI 음성으로 만든 사례별 웹 UI·RAG 시연

> 첫 번째 발표 사례는 [초인종·노크·개 짖음 소리 순서의 새 시연](44_방문_상황_음원_RAG_시연.md)으로 교체했다. 아래 첫 번째 영상은 이전 실험 기록이다.

## 목적과 출처

기존 Windows TTS 음성은 발표용으로 기계적으로 들려 [Google Gemini 3.8 Flash TTS](https://ai.google.dev/gemini-api/docs/speech-generation)로 같은 한국어 문장을 새로 생성했다. **음성 생성 모델**은 `gemini-3.8-flash-tts`이며, **PetMind RAG의 사실 선택 모델**은 기존 설정대로 `gemini-3.5-flash-lite`다. 둘은 별도 모델이다. 음성 생성 결과와 SHA-256은 Git 제외 `artifacts/ai_sound_demo_20261012/natural_voice_manifest.json`에 기록했다.

짖음은 AI가 만든 것이 아니라 [FSD50K](https://zenodo.org/records/4060432) 공개 음원 ID `15791`(업로더 `laurent`, [CC BY 3.0](https://creativecommons.org/licenses/by/3.0/))이다. 생성 말소리와 공개 짖음의 첫 5초를 섞었다. 말소리만 있는 대조 사례도 포함한다. 이는 **실제 집 안 녹음이 아닌 합성 시연**이며, 이 원본은 이전에 검토한 자료이므로 새 독립 정확도 검증이 아니다. 모든 시험 비율과 해시는 Git 제외 `artifacts/ai_sound_demo_20261012/natural/manifest.json`에 있다.

## 각각 실제 웹 UI에서 수행한 일

별도 SQLite DB, API 포트 8013, Flutter 웹 포트 8024에서 **브라우저 파일 선택 → 공개·생성 출처 입력 → 저장 동의 → 업로드·분석 → 시연 담당자 의견 → 귀가·종료 → RAG 질문 → 근거 열기 → RAG·케어 평가**를 세 번 반복했다. 이번에는 API로 음원을 사전 등록하지 않았다. 각 요청의 응답과 브라우저 화면은 `natural/ui_case_results.json` 및 아래 영상에 남겼다.

| 사례 영상 | 5초 입력 | 실험 후보 LSTM 점수 / 기준 0.900 | LSTM 짖음 후보 창 | 시연 담당자 의견 | RAG 근거 |
|---|---|---:|---:|---|---|
| `PetMind_case_1_detected.mp4` | 짖음 + 생성 말소리 | **0.960** | 1/1 | 반려견 소리 | 관찰 #1, 모델 창 1/1, 의견, 합성 출처 |
| `PetMind_case_2_missed.mp4` | 같은 짖음 + 더 큰 생성 말소리 | **0.708** | 0/1 | 판단 어려움 | 관찰 #2, 모델 창 0/1, 의견, 합성 출처 |
| `PetMind_case_3_speech_only.mp4` | 생성 말소리만 | **0.081** | 0/1 | 기타 소리 | 관찰 #3, 모델 창 0/1, 의견, 합성 출처 |

세 RAG 호출 모두 `gemini:gemini-3.5-flash-lite:fact-selection`, 실패 없음, 로컬 기록 검색이었다. Gemini는 서버가 계산한 사실 ID를 선택했고, 최종 한국어 문장은 서버의 근거 문구로 표시했다. 관찰 수치 자체를 Gemini가 계산하지 않는다.

외출 화면에는 **다음 확인 제안**을 추가했다. 이 안내는 Gemini가 처방을 생성한 결과가 아니라, RAG가 선택한 현재 LSTM 근거와 시연 담당자의 확인 의견을 코드가 대조한 결과다. 각 제안에서 관찰 근거 버튼으로 원본 기록을 열 수 있다. 사례 1은 전후 상황 기록과 다음 외출 비교, 사례 2는 원본 재청취와 주변 소음 확인, 사례 3은 다른 소리로 표시된 구간만으로 케어 조치를 권하지 않는다는 내용이다. 제안이 없거나 근거가 부족한 경우에는 억지로 표시하지 않는다. 별도 `RAG·케어` 화면의 케어 제안과는 구분한다.

`RAG·케어` 화면도 이번 관찰의 LSTM 분석 창 수·후보 창 수·시연 담당자 의견·공개 시연 출처를 근거로 받도록 수정했다. 이전 시연 음원을 검색하면 `user_audio`라는 저장 유형 대신 **공개·생성 시연 자료**라고 보여준다. Gemini가 근거 검증을 통과한 사례 2는 `gemini-3.5-flash-lite` 답변이고, 사례 1·3은 근거 불일치 또는 형식 오류로 **기본 판단(대체 동작)**을 표시했다. 세 결과는 각각 전후 상황과 다음 외출 비교, 불확실한 소리 원본 재청취, 다른 소리로 확인된 구간의 케어 조치 보류다. 모델 제공자와 대체 동작을 영상에 그대로 남겨 Gemini가 세 제안을 모두 작성했다고 주장하지 않는다.

검토 중 Gemini가 사례 3의 `기타 소리` 확인 의견을 `불확실`로 바꾸거나, 사례 2의 **분석 창 1개·후보 창 0개**를 **분석 창 0개**로 잘못 적은 응답이 있었다. 해당 문구를 채택하지 않도록 현재 음성 근거와의 일치 검사를 추가했다. 이는 모델 자체 정확도 향상이 아니라 부정확한 케어 설명을 막는 출력 검증이다.

**주의:** 말소리만 있는 사례에서도 에너지 기준 소리 후보가 3회 기록됐다. 이것은 LSTM의 **개 짖음 소리 후보 0/1창**과 다른 지표다. 이번 점검 중 RAG 질문의 “개 짖음 소리 후보” 표현을 검색 규칙이 놓치는 문제를 발견해 수정했다. 수정 후 세 답변 모두 LSTM 창 수를 근거에 포함한다. 후보 점수는 정확도나 확률이 아니며, 5초 창은 실제 짖음 횟수나 정확한 발성 시각이 아니다.

## 발표용 파일과 재현

세 영상은 Git 제외 `artifacts/ai_sound_demo_20261012/natural/`에 있다. 각각 앞 5초에 **해당 실제 시험 음원**을 재생하고, 이어서 웹 UI의 업로드·의견·RAG 조작 화면, 다음 확인 제안·근거 버튼, 별도 케어 평가 화면을 보여주며 마지막 근거 카드를 10초간 표시한다. 각 화면을 읽을 시간을 둔 최종 영상 길이는 사례별 약 **78초, 75초, 75초**다. 영상 속 반려견 확인 표시는 실제 보호자의 답이 아닌 **시연 담당자 의견**이다. 합성 자료는 기본 모델의 학습이나 실제 반려견 장기 기록으로 사용하지 않는다.

재현 코드: `scripts/generate_natural_demo_voice.py`, `scripts/prepare_ai_sound_demo.py --voice gemini38`, `scripts/record_natural_voice_cases.cjs`, `scripts/build_natural_case_videos.py`. 웹 녹화에는 별도 DB와 `PETMIND_AUDIO_LSTM_CHECKPOINT=household_bark_candidate.pt`를 사용했다. 실험 후보는 기본 운영 체크포인트로 승격하지 않았다.

검증: 전체 Python 테스트 **150개 통과**, Flutter 테스트 21개 통과, `flutter analyze` 문제 없음. 세 음원 업로드·의견·Gemini RAG·다음 확인 제안·근거 열기·케어 평가는 실제 웹 조작으로 확인했다. 세 MP4는 영상·음성 디코딩, 각 사례의 RAG·제안·케어 화면과 마지막 근거 카드를 확인했다.
